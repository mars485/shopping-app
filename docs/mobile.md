# Мобильный клиент Shopping

Expo SDK 58, React Native 0.88, React 19, TypeScript 6. Навигация — Expo Router (`src/app`), состояние — собственные провайдеры на React Context + `useReducer`, без внешних state-библиотек.

## Структура

```
src/app/                 экраны (файл = маршрут)
  _layout.tsx            провайдеры: SafeArea → Theme → Auth → Lists
  index.tsx              заставка и редирект по статусу авторизации
  sign-in.tsx            вход
  sign-up.tsx            регистрация
  lists/index.tsx        списки, поиск, создание
  lists/[id].tsx         детали списка, товары, шаринг
  settings.tsx           профиль, тема, проверка API, выход
src/api/                 ApiClient (fetch, таймауты, ошибки) и ShoppingApi
src/state/auth.tsx       сессия, SecureStore, 401 → выход
src/state/lists.tsx      списки, оптимистичные мутации, кэш, автосинк
src/components/          UI-кит (Button, TextField, Sheet, Banner, Avatar…)
src/lib/                 формат денег/количества, валидация, JWT, storage
src/theme/               палитры light/dark, отступы, радиусы, типографика
```

Точка входа приложения — `expo-router/entry` (см. `main` в `package.json`). Файлы `App.tsx` и `index.ts` остались от шаблона Expo и в рантайме не используются; удалять их не требуется, но и правки в них ни на что не влияют.

## Поток данных

1. `AuthProvider` при старте читает сессию из SecureStore. Пока идёт чтение — статус `loading`, экран `index` показывает заставку.
2. После входа `ListsProvider`:
   - поднимает кэш из AsyncStorage (мгновенный показ списков),
   - запрашивает `GET /lists`, обновляет кэш и `lastSync`.
3. Мутации (`toggle`, `delete`, `update`) применяются оптимистично, затем подтверждаются ответом сервера; при ошибке состояние откатывается к снимку до изменения.
4. `401` в любом запросе → `expireSession()` и переход на экран входа с сообщением «Сессия истекла».
5. Автосинхронизация: при возврате приложения на передний план и при фокусе экрана, но не чаще одного раза в 15 секунд.

## Офлайн-поведение

- Последний успешный ответ `GET /lists` и все локальные изменения кэшируются в AsyncStorage по ключу пользователя.
- При сетевой ошибке данные остаются на экране, появляется баннер «Офлайн», кнопка «Повторить» запускает синхронизацию.
- После восстановления связи (возврат в приложение, pull-to-refresh) кэш перезаписывается серверным состоянием — сервер остаётся источником истины.

## Безопасность

- Токен и e-mail хранятся в `expo-secure-store` (Android Keystore, iOS Keychain); на web — fallback в AsyncStorage.
- Токен не логируется, не попадает в кэш списков и не отправляется никуда, кроме `Authorization` заголовка.
- Клиент не хранит пароль; после логина используется только JWT.
- `sub` из JWT используется локально, чтобы отличать свои списки от общих (бэкенд не отдаёт «мой id» отдельным эндпоинтом).
- Все сетевые запросы идут по HTTPS; таймаут 15 секунд, отмена по `AbortController`.

## Интерфейс

- Дизайн-токены в `src/theme/tokens.ts`: светлая и тёмная палитры, радиусы, отступы, типографика.
- Светлая/тёмная/системная тема, выбор сохраняется в AsyncStorage.
- Крупные карточки списков с прогресс-баром и суммой, шторки для создания списка, товара и шаринга, круглая кнопка-действие, тактильный отклик при отметке товара (`expo-haptics`).
- Русская локализация, корректные склонения (`pluralRu`), формат денег `1 234,50 ₽`, ввод дробных чисел через запятую.

### Интеграционные тесты против живого API

`src/api/integration.test.ts` по умолчанию пропускается. Если задан `SHOPPING_E2E_URL`, он поднимает двух пользователей, создаёт список, проверяет CRUD товаров, подсчёт суммы, шаринг, права владельца/участника и удаление.

```powershell
# локальный бэкенд на SQLite
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install fastapi "uvicorn[standard]" pydantic "sqlalchemy>=2,<3" PyJWT
$env:PYTHONPATH = (Get-Location).Path
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# в другом окне
cd mobile
$env:SHOPPING_E2E_URL = "http://127.0.0.1:8000"
npm run test:integration
```

Проверено: 10 интеграционных тестов проходят на `backend/app/main.py` (SQLite). Тест создаёт уникальных пользователей на каждый запуск, поэтому против продакшна запускайте только осознанно.

## Известные ограничения

- Нет переименования списка и выхода из общего списка — этих эндпоинтов нет в API.
- Нет realtime-синхронизации (WebSocket): обновление по фокусу, pull-to-refresh и возврату в приложение.
- Нет push-уведомлений.
- Web-сборка работает, но не является целевой платформой.
